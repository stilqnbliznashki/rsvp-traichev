# Дизайн на API

## Текущо състояние

ASP.NET Core API проектът е инициализиран с поддръжка на контролери и Swagger за разработка. Все още няма контролери на приложението или крайни точки за системата за резервации.

## Предложени конвенции — потвърдете преди реализация

- Използвайте маршрути, ориентирани към ресурси и с имена в множествено число, под `/api/v1/`.
- Използвайте последователно HTTP методите и статус кодовете; валидирайте DTO обектите на заявките при входа.
- Дръжте обектите за съхранение отделно от публичните DTO обекти за заявки и отговори.
- Документирайте поведението на крайните точки и отговорите при грешка в OpenAPI.
- Екипът трябва да избере конвенции за странициране, филтриране, удостоверяване, оторизация и формат на грешките.

## Възможни области на ресурсите (не са окончателно решение за крайни точки)

Профили, служители, услуги, работно време/заетост, календари и резервации.

## Шаблон за договор на крайна точка

За всяка крайна точка документирайте: метод и път, предназначение, оторизация, схема на заявката, успешен отговор, отговори при грешка, валидация и примерен работен процес.
